# Spec — Local end-to-end integration (E)

Branch: `local/e-integration` (local only, push blocked by config). Base: `feat/stats-results-tab`.
Goal: a working app that runs a real measurement end to end, without waiting for other teammates'
PRs. Nothing here is pushed; pieces that prove useful go upstream later as normal PRs by their owner.

## 1. Constraints

- `src/ai_share_of_voice/schemas/` stays unchanged. New code adapts to the contracts, not the other way.
- Every real component has a simulated twin (`LLM_MODE=simulated`), so `make check` never calls an API.
- Spending cap enforced in one place (the model client); CrewAI agents never get a raw key (see `agents/factory.py`).
- Analysis stays deterministic code (`stats/`, `tools/stats_tool.py`); the model only answers and writes text.
- `.env` is never read by tooling or committed; only `.env.example` documents variable names.

## 3. Requirements

R1. `llm_client.py`: `ModelClient` that returns `(schema_instance, schemas.llm.Usage)`, raises
`exceptions.BudgetExceeded`, logs every call, supports `simulated` and `live` modes, and separate
subject / agent / vision models.
R2. Real nodes (`nodes_real.py`): same signatures as `make_fake_nodes`, built from `NodeDeps` + client.
  - questions: load `data/questions_es.csv` or `questions.csv` by `Brief.language`.
  - sampling: ask the subject model each question once per batch; store raw answers in the run folder.
  - metrics: mention tool → `answers.csv` → stats tool → real `should_stop`.
  - research: real search (or fixture list in simulated mode), robots.txt, untrusted wrapping.
  - screenshots: vision on our own convergence/share chart (guaranteed path).
  - write_draft / skeptic: writer via model; skeptic node from `agents/skeptic.py`.
  - finalize: `automation/finalize.py`.
R3. `app.py` (Gradio): Brief tab → background run with event stream and spend bar → approval →
Results tab (`ui/results_tab.py`).
R4. `make check` green; new tests for R1 and R2 in simulated mode.
R5. One live run under 0.50 USD, logged in `runs/`.

### Product direction: any sector, not only the demo (added 2026-11-02)

Madrid food delivery is the demo. The product must serve a client of any sector and city
("where can I buy clothes in Valencia?"), and record every question with every business the
answer names, even when nobody told us to track it.

R6. Question panel for any sector.
  - Source, in order: an approved panel file (the demo CSVs, or one saved by a previous run of the
    same client) → otherwise generated by the agent model from sector, city and language.
  - Generated questions are checked in code: unique, 5–500 chars, and they never contain a tracked
    brand name or variant (a question that names the brand measures nothing). Rejected ones are
    regenerated once, then dropped.
  - Intents mixed: recommendation, where-to-buy, best-of / top-N, comparison, budget, nearby.
  - The panel is saved to `runs/<id>/questions.csv` and can be reused: the same panel across runs
    makes runs comparable (a change is due to the model, not to different questions).
R7. Discovery of every business named in an answer.
  - Per answer, the agent model lists every brand, store, app or website named (name, kind, URL if
    any). The answer is untrusted data, delimited in the prompt.
  - Code keeps only names that literally appear in the answer text (normalized like
    `normalize_brand_name`): a name the model invented is dropped. Names matching a tracked brand
    or variant are mapped to it.
  - Stored per batch in `runs/<id>/discovered/batch_NNN.jsonl` with `question_id`: question →
    businesses is recorded for every answer.
  - Report: untracked businesses ranked by mention rate (share of answers), with Wilson interval and
    number of questions; suggest adding as competitor above a threshold (proposed 10%, decision 7).
  - Local file format, no change to `schemas/`. Upstream later as decision 7 with J.
R8. (Parked) Discovery-only run for a new client with no known competitors. Needs `Brief` to accept
  fewer than two competitors: schema change, so not in this branch.
